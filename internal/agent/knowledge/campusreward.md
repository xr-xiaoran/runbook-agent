CampusReward 发奖 pending 待处理：抽奖事务把中奖结果和 Outbox 发奖待办一起提交。若用户中奖但一直没有权益，先检查 ROLE 是否只有 api、后台 worker 是否运行，以及 API 和 worker 的 DB_PATH 是否指向同一主机的同一个绝对路径。恢复 worker 后扫描 pending。不要直接修改库存或重复创建抽奖。当前权益只是本地数据库模拟记录。

CampusReward 发奖失败 dead：最多尝试 5 次，fail_first 是测试失败注入参数，失败后按 1、2、4、8 秒等退避。达到预算会转 dead。管理员重放会重置尝试次数，保留历史并增加版本；fail_first=5 重放仍会失败，重放不是修复根因。先检查事件与故障原因，再人工判断是否重放。

CampusReward 签到机会：同一用户、同一活动、同一 UTC 日期只能签到一次。UTC 日界对应北京时间早上 8 点。重复签到不增加第二次机会。活动只有 active 时才允许签到。当前没有学校身份、定位或实际到场核验。

CampusReward 库存与幂等：使用条件 UPDATE stock>0 扣库存，影响行数为零表示库存耗尽。抽中但库存耗尽记 stock_exhausted，仍消耗机会，不隐式重抽。客户端超时后应复用原 Idempotency-Key；同用户同键返回原结果，换活动返回 409。系统数据库错误整笔事务回滚。

CampusReward 权限 401 403 404：USER_KEYS 是服务端预配置用户密钥，不是 JWT。管理员创建发布关闭活动并重放，普通用户仅查看本人结果。401 检查 Bearer 密钥和当前终端环境变量；403 检查管理员权限；查询别人的结果返回 404。不要把真实密钥贴入工单或日志。
